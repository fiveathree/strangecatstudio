# 規格與多 AI 協作流程

這個資料夾是設計、開發、驗收三方的共用溝通區。

| 角色 | 由誰做 | 負責章節 |
|---|---|---|
| 需求、拍板 | 用戶 | 1、2，以及 3.5 的決定 |
| 設計 | ChatGPT Go | 3 |
| 開發 | Claude（Claude Code） | 4，以及把其他人的回覆寫入檔案 |
| 驗收 | Gemini Pro（Google） | 5 |

## 流程

1. **開新檔**：複製 `_template.md`，改名為 `YYYY-MM-功能名.md`（例如 `2026-10-otp-login.md`）。可以直接叫 Claude 開。
2. **定需求和驗收標準**：用戶填第 1、2 節（可以請 Claude 幫忙起草），確認後才進入設計。
3. **設計**：把整份檔案貼給 ChatGPT Go，附上下面的「設計提示」。把回覆貼回給 Claude，Claude 原文寫入第 3 節。
4. **開發**：Claude 實作、自測，填第 4 節，commit 並推上 repo。
5. **驗收**：把整份檔案（加截圖或測試網址）貼給 Gemini Pro，附上「驗收提示」。回覆貼回給 Claude，原文寫入第 5 節。
6. **退回就修**：Claude 按第 5 節修正，在第 6 節記錄，再回到第 5 步，直到「通過」。

ChatGPT 和 Gemini 不能直接改 repo，所以檔案一律由 Claude 寫入；Claude 不改寫他們的判斷。

## 設計提示（貼給 ChatGPT Go）

```
你是這個功能的 UI/UX 設計師。下面是規格檔。
請只填寫「3. 設計」整節，用 Markdown 回覆，照檔案內的小標題。
- 用文字規格，色碼、字級、間距都要寫具體數值；有圖也要附數值。
- 每個畫面列出元素和互動，並寫清楚載入中、空白、錯誤、成功狀態。
- 文案中英對照；中文用標準書面繁體中文，不要用粵語。
- 每條驗收標準（第 2 節）都要在設計中找得到對應。
- 需求不清楚的地方不要自己假設，列在「3.5 未決定事項」。
（貼上規格檔）
```

## 驗收提示（貼給 Gemini Pro）

```
你是這個功能的驗收測試員。下面是規格檔，以及截圖／網址。
請只填寫「5. 驗收結果」整節，用 Markdown 回覆。
- 逐條對照「2. 驗收標準」，每條判斷：通過、不通過、未能驗證，並寫理由。
- 沒有看到證據（截圖、網址內容、程式碼）的，一律寫「未能驗證」，不可以當作通過。
- 再對照「3. 設計」，列出實際與設計不同的地方。
- 其他問題按嚴重程度分：必修／建議／小事。
- 最後給結論：通過或退回。
（貼上規格檔，附截圖或網址）
```

## 注意

- 公開 repo 的規格檔會被所有人看到：不可寫私人資料、密鑰、電郵、金額。
- 一個功能只用一個檔；大功能可以拆成幾個檔，互相連結。
- 已驗收的檔案保留，當作功能紀錄。
